# OpenAI 过载回避

管理后台「系统设置 → 网关」的「OpenAI 过载回避」默认关闭。它处理 OpenAI OAuth / SetupToken 文本请求明确返回的容量错误（如 `server_is_overloaded`、`slow_down` 或已识别的过载文案），包括 HTTP 错误和 HTTP 200 SSE 内的 `error` / `response.failed`。

开启后默认优先换账号重试：只在尚未输出有效内容时进入现有换号流程，沿用 `gateway.max_account_switches` 上限；已输出文本、工具调用等内容后不重放。关闭「过载时优先换账号重试」则保留原有同账号重试策略，连续过载统计仍生效。此功能不能保证全池过载时请求成功。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用 | 关闭 | 总开关，关闭时维持现有行为 |
| 过载时优先换账号重试 | 开启 | 受总开关控制 |
| 统计窗口 | 60 秒 | 同一账号的文本模型合并统计，详情保留触发模型 |
| 过载次数阈值 | 1 | 范围 1–100；窗口内达到 N 次即回避，设为 1 时首次过载立即回避，同一 HTTP 请求的重试与重复 SSE 错误帧只计一次 |
| 首次回避时长 | 60 秒 | 后续失败按 1、2、5、10 倍递增，加入约 ±10% 抖动 |
| 最大回避时长 | 600 秒 | 包括抖动在内不超过此上限，最多可配置 7200 秒 |

只以窗口内去重后的过载请求数决定是否回避，达到 N 次即触发，不再设置或检查过载比例。其他请求成功不会稀释已有过载次数；尚未触发冷却时，同一请求在同账号重试成功会撤销该请求的过载计数。任一文本模型触发后，暂停整个账号的文本调用。

账号进入现有“临时不可调度”：列表可筛选，详情显示触发模型、次数、阈值、窗口及截止时间；“恢复状态”和清除临时不可调度会同步重置 Redis 计数、冷却、验证租约。手动恢复提升状态代次，旧请求的延迟结果不能再次写回暂停。仅写可恢复状态，不禁用账号或修改手动调度开关。

冷却到期后，整个账号跨文本模型同时只允许一个真实请求验证，跨实例由 Redis 原子协调。三个验证请求成功后恢复正常调度并降低一级冷却；验证过载则立即升级冷却。请求取消释放验证租约，进程异常则由租约超时恢复。到期后的单请求恢复阶段不再计入列表的固定冷却时间。

**Web 生图例外**：ChatGPT Web 生图继续可用，也不参与文本计数或恢复验证。只有明确标记为文本过载的暂停可被 Web 生图跳过；认证、代理/传输故障、手动停调和 Web 图片配额冷却仍生效。多个暂停原因竞争时，保留更严格原因，不缩短截止时间。容量统计相应扣除文本容量并保留可用 Web 生图容量。

升级时忽略旧配置中的 `failure_rate_percent`，保留已保存的次数阈值、开关和冷却时长；未保存过配置时次数默认 1。管理员接口不再返回或保存比例字段，旧客户端提交该字段时也会忽略。已保存阈值为 3 的部署仍使用 3，可在设置中改为 1。

429 默认回避、配额重置时间、529 冷却和账号认证保持原有语义。图片、其他平台、影子账号和 WebSocket 客户端长连接不产生本功能的计数；文本账号级暂停仍会被这些入口的既有账号状态检查执行，只有 Web 生图例外。已有长连接包含多个独立轮次，不能作为单个 HTTP 请求计数。

设置独立保存在 `openai_capacity_cooldown_settings`，管理员 GET / PUT `/api/v1/admin/settings/openai-capacity-cooldown`。修改后本实例立即生效，其他实例最多约 30 秒刷新。Redis 读写失败时跳过本功能的新回避决定；已写入数据库的临时暂停仍执行到截止时间。后台恢复若无法清除 Redis 状态会返回错误，避免显示恢复成功却继续回避。日志 `openai.capacity_cooldown_tripped` 记录账号 ID、触发模型、次数、统计请求数、级别和截止时间，不记录请求正文或凭证。

从旧的“账号＋模型”版本升级时，新账号级 Redis 状态独立计数，旧模型级记录按原 TTL 自然过期；不依据历史日志批量暂停账号。已有开关、阈值和时长保留，后续新触发写入现有临时不可调度字段，无需数据库迁移。

发布镜像不等于线上启用；部署后仍需管理员主动打开总开关。
