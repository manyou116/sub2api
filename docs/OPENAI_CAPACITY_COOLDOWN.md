# OpenAI 过载回避

管理后台「系统设置 → 网关」的「OpenAI 过载回避」默认关闭。它处理 OpenAI OAuth / SetupToken 文本请求明确返回的容量错误（如 `server_is_overloaded`、`slow_down` 或已识别的过载文案），包括 HTTP 错误和 HTTP 200 SSE 内的 `error` / `response.failed`。

开启后默认优先换账号重试：只在尚未输出有效内容时进入现有换号流程，沿用 `gateway.max_account_switches` 上限；已输出文本、工具调用等内容后不重放。关闭「过载时优先换账号重试」则保留原有同账号重试策略，连续过载统计仍生效。此功能不能保证全池过载时请求成功。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用 | 关闭 | 总开关，关闭时维持现有行为 |
| 过载时优先换账号重试 | 开启 | 受总开关控制 |
| 统计窗口 | 60 秒 | 同一账号、实际上游模型分别统计 |
| 过载次数阈值 | 1 | 范围 1–100；窗口内达到 N 次即回避，设为 1 时首次过载立即回避，同一 HTTP 请求的重试与重复 SSE 错误帧只计一次 |
| 首次回避时长 | 60 秒 | 后续失败按 1、2、5、10 倍递增，加入约 ±10% 抖动 |
| 最大回避时长 | 600 秒 | 包括抖动在内不超过此上限，最多可配置 7200 秒 |

只以窗口内去重后的过载请求数决定是否回避，达到 N 次即触发，不再设置或检查过载比例。其他请求成功不会稀释已有过载次数；尚未触发冷却时，同一请求在同账号重试成功会撤销该请求的过载计数。已触发的冷却通过恢复验证退出：到期后，每个账号和模型同时只允许一个真实请求验证，跨实例由 Redis 原子协调。三个验证请求成功后恢复正常调度并降低一级冷却；验证过载则立即升级冷却。请求取消释放验证租约，进程异常则由租约超时恢复。

升级时忽略旧配置中的 `failure_rate_percent`，保留已保存的次数阈值、开关和冷却时长；未保存过配置时次数默认 1。管理员接口不再返回或保存比例字段，旧客户端提交该字段时也会忽略。已保存阈值为 3 的部署仍使用 3，可在设置中改为 1。

429 默认回避、配额重置时间、529 冷却、账号认证和账号状态保持原有语义；本功能只维护 Redis 中的临时容量状态，不将账号标记为封禁。图片、其他平台、影子账号和 WebSocket 客户端长连接不使用此统计策略。已有长连接包含多个独立轮次，不能作为单个 HTTP 请求计数。

设置独立保存在 `openai_capacity_cooldown_settings`，管理员 GET / PUT `/api/v1/admin/settings/openai-capacity-cooldown`。修改后本实例立即生效，其他实例最多约 30 秒刷新。Redis 读写失败时跳过本功能的回避决定，不因保护服务异常新增账号封禁。日志 `openai.capacity_cooldown_tripped` 记录账号 ID、模型、次数、比例分母、级别和截止时间，不记录请求正文或凭证。

发布镜像不等于线上启用；部署后仍需管理员主动打开总开关。
